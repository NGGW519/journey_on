# 로드뷰 육안 검수 체크리스트 — phase1(1단계 관광지 권역)

작성: qa-inspector, 2026-11-17. 대상: interim 데이터(Copernicus GLO-30 DSM + OSM)로 만든 phase1 씬(Unity 임포트 2026-11-17 18:14).

## 쓰는 법

- **사람만** 브라우저에서 카카오맵·네이버지도 로드뷰를 열어 **눈으로만** 본다. 캡처·저장·추적·가공은 하지 않는다(기획서·약관). 에이전트는 로드뷰에 접근하지 않는다.
- 아래 WGS84 좌표(위도, 경도)를 지도 검색창에 넣고 가장 가까운 로드뷰 지점을 연다. "볼 방향"은 방위각(북 0°, 동 90°)이다.
- Unity에서 같은 자리를 보려면 Scene 뷰나 플레이 모드 F 비행으로 아래 Unity 좌표에 간다.
  - 좌표 규칙: 원점 E246000 N580000 기준 X = E − 246000, Z = N − 580000, Y = 해발 m.
  - Y는 모델 지면 + 1.7 m(눈높이)다. 다리 위 지점은 모델에 다리가 없어서 추정값을 적었다.
- 좌표 근거:
  - OSM 원천 `data/raw/open/osm/phase1/*.geojson`의 객체 대표점(EPSG:5186 → WGS84 변환). OSM 객체 id를 함께 적었다.
  - 남이섬 선착장만 OSM 레이어에 객체가 없어서 `docs/decisions.md` D-001 기록값을 썼다.
  - OSM 좌표는 수 m 어긋날 수 있다.
- "모델 현재 값"은 2026-11-17 산출물(`data/out/phase1/tiles/*/buildings.json`, 높이맵) 기준이다. 층수는 OSM 기본값(1층)인 경우가 많다.
- 결과 칸에 O(일치) / X(불일치) / ?(판단 불가)와 메모를 적는다. 불일치는 지점 번호와 함께 `_workspace/`의 다음 QA verdict로 넘긴다.
